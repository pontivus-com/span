## 1. Authority, purpose, and scope

This document contains the solution design and its associated implementation
tasks for bugfix release 0.10.3. Sections 1–11 define the solution; §12 orders
the work and §13 records completion. It is not a new requirements layer.
The authority chain is [AGENTS.md](../../AGENTS.md), [requirements pyramid](../requirements-pyramid.md),
[goals](../goals.md), [foundations](../foundations.md), [lifecycle contract](../lifecycle-contract.md),
[functional design](../functional-design.md), then [technical design](../technical-design.md).
References below use their G, A, F, L, and FD identifiers rather than restating them.
Public-contract decisions are now recorded in their owning amended layers.
This plan does not override those layers or claim the installed code conforms.

The current request authorizes closing documentation gaps: the relevant
behavior-class audit and amendments to lifecycle, functional and technical
authority from the accepted baseline and code evidence.
It does not start runtime implementation, bump the
package version, authorize acceptance runs, or authorize publication or Git writes.
Future implementation follows the task boundaries and gates below after explicit
authorization. File paths in task boundaries are relative to the Span root.

The design covers obtain, investigation evidence, retain, receipts, identity,
status, and repeated evidence delivery. It preserves the existing semantic writer,
typed support owner, status computation, store, and three lifecycle operations.
It introduces no model runtime, semantic similarity service, structural index,
automatic conclusion author, delivery ledger, or additional public tool.

## 3. Selected end-to-end flow

1. The agent obtains a surface's current document view without supplying a
   question, request ID, or context. Span evaluates retained support and returns grouped conclusions,
   status, limitations, and explicit omissions.
2. If no usable understanding exists, Span returns a small gap with status and
   available source pointers distinguished from admitted evidence. The host performs structural navigation.
   Explicitly requested excerpts are returned with exact line ranges and identity.
3. The agent investigates and authors a conclusion. It records direct source
   locators/ranges plus the question and semantic owner/scope it already knows.
   Span derives context and observations. A supplied live context is an optional
   alternative, not a mandatory dependency of ordinary capture.
4. Span validates complete scope and support, accepts atomically, and returns a
   compact acceptance with live qualification, status, and exact update/replay
   coordinates. Detailed history remains reachable through `ask(selector=...)`.
5. A fresh caller repeats step 1. After an edit, pure `reconsider` supplies exact
   affected revisions/update versions without issuing a context. A challenge is
   a separate write branch with its own stable request identity.

No step silently converts evidence into semantic conclusions. A CURRENT label
continues to describe declared support, not completeness or semantic truth.

## 4. Obtain and evidence selection

### 4.1 Surface-first reuse

The follow-up evidence in §14 E1 establishes a structural grammar defect, not
only a guidance defect. Select a surface/reference-only ordinary obtain branch:
`question` is not accepted there. Questions remain authored on `record` and
retained as understanding metadata; they are not natural-language lookup keys.

For advanced current retrieval, add a typed `CurrentUnderstandingSelector` to
the existing ask selector union. It carries repository and a returned
understanding ID, uses that understanding's canonical surface/current version,
and composes an Answer/Gap through the existing support/status owners. It never
turns a historical snapshot into a current answer. Unknown IDs return an explicit
lookup rejection with cause; no similarity search or surface substitution occurs.
Existing snapshot and receipt selectors retain their historical/audit meanings.

This replaces ordinary exact-question lookup rather than keeping a competing
legacy grammar. Retire its string-question `no_match` production path in the
new public contract; do not rewrite retained question identities or history.
Amend lifecycle §4.1 and FD-25/28 before code. Update all packaged consumers in
the same candidate and review patch-release compatibility under T02.

The grouped view is the canonical representation for questionless reuse. Its
instruction must identify where conclusions are located without teaching an
unnecessary second exact ask. Do not duplicate statements in both `groups`
and top-level `conclusions` to make the response appear populated.

Pure surface/current-selector reads issue no investigation context and require
no request ID. They still evaluate support freshly and can report operational
failure. A broad gap names missing understanding; it does not claim to answer an
uninvestigated surface. These choices remove read bookkeeping at its producer.

### 4.2 Explicit excerpts, inexpensive gaps

Replace automatic whole-path content admission in `_investigate` with a
contracted evidence-selection path:

- An ordinary broad ask returns status, source pointers and a precise recovery,
  without automatically delivering all file content. An unexamined source pointer
  is not admitted evidence or a claimed current fingerprint. Use existing source
  request/reference carriers without synthesizing missing content identity.
- Extend the canonical ask request with an optional collection of existing
  `EvidenceRequest` carriers for explicit locator/range requests. Selection is
  valid only for the surface/reference form, within the resolved surface, and
  cannot accompany a selector or continuation. This explicit admission branch
  requires a request ID and issues a scoped EVIDENCE_ONLY context; questionless
  pure reads do neither. No duplicate range DTO is added.
- A host can pass ranges from navigation it just performed. For a symbol, use
  its exact host-provided source range; Span verifies locator, bounds, and bytes.
  If that range is unavailable, report the missing evidence selection rather
  than inventing a function boundary or constructing another structural index.
- A whole-file request remains explicit and honestly labeled. Multiple ranges
  retain their individual source positions; concatenated excerpts never imply
  one contiguous span.

Admission and delivery remain separate operations inside the service. Reuse
existing fingerprint/range validation and continuation mechanisms. Response
fitting is applied after selection; a size limit never chooses relevance.

This changes the gap payload/recovery promise in lifecycle §4.1 and the request
grammar. The owning lifecycle/functional amendments are now applied. Exact
byte retrieval is not delegated to an unbound filename: it remains tied to the
selected observation and current source identity.

## 5. Recording and request schema

### 5.1 Use the existing direct-evidence path

The normal file create uses `question`, `conclusion`, and a direct locator, with
explicit support ranges when needed. The locator can derive the single-file
semantic owner. A cross-file conclusion supplies its actual owner/scope and the
complete declared support union. Supporting files do not become extra owners.

Keep context-bound recording for evidence already admitted by Span. It retains
fixed-scope and membership validation. Do not infer an observation's admitting
context, widen a supplied context, or replace an invalid context automatically.
Do not treat reading a current file during record as proof that an earlier test
or observation used those same bytes.

### 5.2 Generate valid alternatives from the canonical contract

In `core/schema/record_wire.py` and the schema projection, express create/update,
target binding, and evidence alternatives as explicit branches with their
required and forbidden fields. Derive schema constraints from the same typed
rules used by runtime validation; do not hand-maintain a second validator in
`shell/mcp/schemas.py`.

Select one canonical set of conditional branch constraints owned by the typed
wire contract. Its decoder/construction validation and schema projection consume
that same declaration. Retaining a flat wire object is acceptable only when
illegal structural combinations are rejected at that boundary; a prettier schema
over independent procedural validators is not. Do not introduce a second DTO
hierarchy just to advertise branches. Test equivalence over valid/invalid cases,
including null/default/empty values and forbidden unknown fields.

Keep the boundary precise: field presence, mutually exclusive evidence modes,
kind/action combinations and required syntactic scope inputs are structural.
Whether a context exists/is live, which target its origin binds, whether evidence
belongs to it, whether the owner covers semantic scope, and whether an expected
version is current require authoritative state. Those checks stay in the existing
lifecycle/support/store owners and are not repeated in the decoder. The supplied
context's origin cannot safely be guessed from the presence of `context_id`.

Validate independent structural problems before service work. A rejection can
name multiple independent conflicts and exact corrective fields in one result;
do not continue source admission after a determinative binding failure merely
to collect errors. Operational failures remain `Unavailable`. Preserve atomic
acceptance, replay resolution before dependency checks, and update version checks.

Generate a short description and a small set of valid examples from those
branches. Keep advanced variants in the schema rather than repeating the full
protocol in every description and skill. Preserve discriminators needed for
unambiguous typed decoding; remove tags only where the canonical generator can
prove a unique alternative. Test actual host delivery, including unknown fields.

For the proposed ask grammar, pure surface/reference reads carry no request ID;
explicit evidence admission requires one; selector/continuation branches carry
their own exact bindings. Express this in the canonical alternatives, not a
permissive optional field followed by hidden requirements. The current schema
mismatch in §14 E2 must not be carried into the replacement grammar.
Do not derive retry identity from question text or source content.

## 6. Context continuity and identity

### 6.1 Context continuity: bind the producer and preserve failures

The reported recently-issued-context failure is an accepted observed defect.
The original transcript is unavailable; it is not an investigation or release
prerequisite. Code-based reproductions in §14 E8 establish a live-context unknown
failure and concealed context/store errors. They identify repairs without
requiring a speculative assertion about which historical call took which path.

**Binding defect.** Current ask returns a bare context ID, while a later record
independently chooses its repository route. That permits a live valid reference
to be looked up in another store and reported unknown. Correct the boundary:
use one canonical typed `InvestigationContextRef` containing repository and
context identity, emitted from the owning persisted context. Context-bound record
and verification branches carry that reference and a new write request ID;
their route derives from the reference, not a second caller-authored repository.
Forbid a separate repository override in that branch. Direct-evidence branches
retain their explicitly supplied repository and derive context internally.

Replace bare context-ID ingress/egress coherently in the affected lifecycle
consumers; do not retain a legacy parser, scan other stores for a matching UUID,
or infer a repository from a path. Route from the parsed typed reference, then
validate membership/liveness in the owning store. This is a reference to the
existing context, not another context representation/writer or token registry.
It creates no durable state: creation, expiry, abandonment, replay and reaping
remain owned by the existing context lifecycle. The reference itself grants no
authority and must not bypass repository or evidence validation.

**Failure-production defect.** Remove `_investigate`'s catch-all `ValueError`
conversion into an ordinary Gap. In the approved request branches, context
issuance conflicts must reach the typed conflict boundary; actual store/provider
unavailability must reach Unavailable. A failed admission cannot be represented
as unassessed understanding with a null context and the failure erased. Preserve
ordinary gaps only for their declared semantic absence/support conditions.

**Recovery defect.** `_get_context_in` currently collapses missing references
into `LifecycleStoreError`, and the adapter's recovery asks agents to read an
internal operational state. Make missing/invalid context-reference rejection a
typed lifecycle result at the owning lookup boundary, with exact repository/ID
and available public action. Genuine store access failures remain Unavailable.
Continuation must likewise not infer that an absent context was reaped. Report
absence honestly; preserve independently held source evidence and allow the
existing direct-evidence recording path when applicable. Never silently replace
a context, renew TTL, or automatically re-ask as the primary solution.

Verify the complete matrix in T07, including correct binding, independent callers,
restart, two-minute reuse, expiry, abandonment and replay of accepted writes.
No new tombstone table, process cache, timeout increase or failure-message
substring classification is justified by these findings. The canonical layer-2/3 amendments now govern reference and failure-boundary
implementation.

### 6.2 Reduce handling, preserve distinct identities

Select caller-owned stable request identity for writes and explicit evidence
admission in 0.10.3. Evidence E3 shows no current transport-to-intent identity
binding and does not establish host-generated IDs as stable retries. Two distinct
intentional acts may have identical payloads, while a retry must reuse the first
act's identity. Content hashes and per-network-request IDs cannot decide that.
Pure obtain is read-only under §4.1 and carries no identity/context. Keep
observation/context identities derived by Span and update lineage/version explicit.

This is the release's residual responsibility, not a claim of zero manual
identity management. A future host-owned path requires captures proving identity
survives loss after commit, reconnect/restart and retries while distinguishing a
new identical operation. No host token registry or automatic fallback is selected.

Return the understanding ID, conclusion revision reference, and expected update
version together once in acceptance/reconsider results. The agent copies returned
coordinates; it does not resolve internal identities in a separate operation.
Do not introduce a universal opaque token that hides all identities in a new
registry. Direct create remains usable without context or observation IDs.

## 7. Compact results and audit retrieval

Revise canonical public result carriers in `core/model/`, not the MCP adapter's
JSON after serialization. The adapter remains a transport boundary. Use the same
canonical public object for text and structured channels; evaluate how each
supported host counts and exposes them before changing channel delivery.

For ordinary acceptance, retain one copy each of acceptance identity/version,
revision coordinates, live support state and material limitations, owner status,
and a receipt reference. For answers, retain statements, assertion nature, scope,
source evidence/ranges, per-conclusion support qualification, and surface status.
Remove repeated references and repeated verification-run bodies from nested
qualification where the containing object already identifies the same subject.
Preserve failed support findings; compactness must not conceal invalidation.

Keep full immutable receipts in the existing store. The existing receipt selector
retrieves them. For historical understanding, retain the exact understanding
selector. Detailed qualification retrieval must use that same canonical evaluator
against exact references and identify evaluation time; if the existing selector
cannot represent this, amend its contract explicitly rather than persisting a
parallel evaluation snapshot or presenting a historical result as current.

Select the following compact field responsibilities for the layer-2 amendment:

| Public result | Required information, represented once |
| --- | --- |
| Understanding acceptance | repository/request identity; commit time and receipt selector; accepted understanding/version; affected conclusion revision coordinates; dependent-effect references; live qualification or explicit unavailability; owning status or explicit unavailability |
| Per-conclusion qualification | exact revision reference; state; evaluation time; material limitations; non-current dependency findings and causes; exact detail retrieval coordinates |
| Answer | surface/status; current statements with nature, scope and source/range references; grouped questions as metadata; per-conclusion qualification; applicable verification identity, command/outcome and qualification; omission/recovery |
| Gap | surface/status; cause; missing understanding; historical references/content where required by contract; source pointers distinct from admitted evidence; selected excerpts/observations/context only for explicit admission; omission/recovery |

Use the existing `UnderstandingSnapshotSelector` with the exact accepted version
for detailed revisions/dependencies and their live support evaluation. Current
`RetrievedUnderstanding` already carries `version`, `conclusions`, `support` and
`challenges` (§14 E7); retain those details and evaluation timestamps. Receipt
retrieval supplies the immutable content digest, accepted effects, context
binding and replay expiry. No new audit selector or qualification store is needed.
Represent an all-current dependency set through its qualification plus exact
detail reference; never suppress non-current findings as a size optimization.

T02 translates this field decision into canonical typed fields and verifies
each required fact's default or detail location; it does not reopen arbitrary
JSON trimming. Bounds retain explicit omission/recovery under FD-55–FD-57.

## 8. Status and repeated evidence

Add owning `SurfaceStatus` to surface gap results through the existing
`compose_surface_status` owner. Answer/Gap status and host notices use that same
computation. Display support distribution before bulky evidence. Keep runtime
availability and structural-provider readiness distinct from semantic support;
a healthy index does not establish CURRENT understanding.

Do not introduce a preflight status tool. A surface ask is already the obtain
moment. Before a surface is chosen, a host notice may describe availability,
but must not assert repository-wide currency from one file's status.

Reuse canonical observations for identical source/range identity. Remove broad
automatic body delivery at the source as described in §4.2. Explicit excerpt
requests deliver to each caller that requests them. Do not suppress bytes because
another agent received them, because the caller is in the same process, or because
an earlier request had the same text. No delivery ledger is introduced. Further
cross-call suppression remains deferred until a host can demonstrate shared
evidence possession and a measured benefit justifies the state lifecycle.
