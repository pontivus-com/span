## 1. Beta-2 outcome

Beta 2 combines three coherent workstreams.

### A. Maintained semantic knowledge: capture → curation → reuse

1. The working engineering agent records supported semantic meaning while its
   evidence and reasoning are fresh.
2. That exact revision is retained as `CAPTURED`, not automatically published
   as shared knowledge.
3. A separate reviewer/curator act accepts a stable exact revision as
   `CURATED`.
4. Ordinary `ask` Answer content is available only while the revision is both
   `CURATED` and its required support is `CURRENT`.
5. Implementation/governance change continues through the existing
   `reconsider`/re-establishment lifecycle.
6. Semantic-preserving `confirm` may inherit an existing curation decision;
   semantic change creates a new CAPTURED revision.
7. Functional Pyramid authority remains independent from curation.

### B. Beta-1 initialization remediation

Beta-1 post-release use exposed two generic defects transferred into this
release:

- **B2-D01 — `span-install` does not execute the existing repository
  initialization contract.** The canonical request/service/provisioning owners
  already exist, but the installer never dispatches them and has no
  administrative ingress for the existing `AuthorityBinding` carrier.
- **B2-D02 — installed production-topology acceptance bypasses that defect.**
  The governed installed fixture directly constructs LifecycleStore state and
  authority bindings instead of proving the installed `span-install` path.

These are Layer-4 composition/verification defects. They do not add a new
Layer-0–3 Functional Pyramid rule.

### C. Public product narrative

The repository and release surfaces present:

```text
knowledge factory
    = broader operating model

Span
    = evidence-backed software knowledge layer

capture
    = evidence-near retained semantic understanding

curation
    = exact-revision shared-reuse qualification

working context
    = task-time projection of CURRENT + CURATED understanding
      plus applicable governing orientation
```

The public thesis remains:

> **Software knowledge must know what it depends on.**

The complementary Beta-2 principle is:

> **Task-local understanding should not become shared knowledge merely because
> one agent established it.**

The concise operating statement is:

> **Working agents capture. Reviewers curate. Span maintains the lifecycle.**

External knowledge-factory/LangChain material is discovery evidence and public
context only. It is not product authority and Span does not claim to implement
LangChain's separate background-curator topology.

The public MCP operations remain exactly:

```text
ask
record
reconsider
```

## 2. Non-goals and hard boundaries

Beta 2 does **not**:

- add a fourth `curate` MCP operation;
- run or schedule a model/background curator inside Span;
- require LangChain, LangSmith or another external framework;
- make curation proof of semantic truth;
- make curation a Functional Pyramid authority layer;
- infer authority, applicability or semantic quality from structure;
- derive authority bindings from Functional Pyramid declarations;
- add another semantic content store, writer, support evaluator or effect engine;
- add DTO/shadow carrier families or compatibility grammar;
- similarity-rank or model-rank pending curation;
- weaken support/currentness requirements;
- auto-curate Beta-1 conclusions during migration;
- silently dual-open schema 14 and schema 15;
- auto-activate Functional Pyramid participation during installation;
- add adopter-specific topology/configuration as a generic Span requirement;
- make external articles/social communication canonical product authority.
