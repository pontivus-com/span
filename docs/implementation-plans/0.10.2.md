## 1. Requested outcome and authority

Semantic understanding must be governed through Span. Agents consult Span before
deriving understanding, retain supported conclusions when established, and
reconsider affected understanding after changes. These are part of completing
the work. Every public agent-facing instruction must communicate that lifecycle
without wording that licenses bypassing it.

The current request explicitly authorizes reformulating rules that undermine
that outcome. Repository rules govern work; requirements-pyramid.md governs
placement and derivation. Product authority flows from goals through foundations,
lifecycle contract, functional design and technical design to projections.
The corrected pyramid is the filter throughout: a defective current requirement
cannot justify retaining its downstream defect. Apply the source-bound correction
specification in §7.1 to its owning layer first, then derive guidance and code.
If a finding exposes another upstream defect, correct that owner before its
consumers. Preserve one owner per rule; downstream guidance references it.

G2 and G6 already establish retention/reuse and replacement of unchecked
semantic documentation. This patch corrects contradictory guidance and the
implementation paths that obstruct those outcomes. It adds no new product goal.
Do not introduce coverage exemptions, documentation disclaimers, or subjective
“worth retaining” qualifications as replacements for the required lifecycle.

The planning-only stage and implementation are complete. Requirements, guidance,
runtime fixes, regressions and 0.10.2 metadata were implemented and merged through
PR #28. Test installations use disposable fixtures; user host configuration was
unchanged by the implementation work. Package/registry publication state is not
part of this repository implementation-closure claim.

## 3. Boundaries and non-decisions

Required scope: owning requirements, all current agent-facing projections,
their distribution and upgrade checks, cold-start notices, stop-time path
delivery, ranged evidence admission and subsequent support checking, relevant
tests, and release metadata.

Keep exactly ask, record, reconsider. Keep the existing typed carriers, semantic
ownership, evidence identity, compare-and-set, receipts, and schema version.
No model calls, automatic semantic author, semantic classifier, confidence gate,
new public operation, or second understanding service.

No persistent obligation ledger, general tool-call blocking, final-answer veto,
or new host enforcement framework. Instructions require lifecycle completion;
the patch must not advertise mechanical enforcement of unobservable reasoning.
No dependency additions, budget increases, broad refactors, or unrelated cleanup.
Do not rewrite historical release notes, captured transcripts, or generated
graft files as though they were current operating instructions.

The completion rule applies to the understanding established and affected by
the work. A reused CURRENT conclusion does not require a duplicate record.
Semantic scope and evidence scope retain their canonical meanings. Preserve
explicit gaps and genuine failures; never fabricate a conclusion to satisfy a
completion instruction. An unsuccessful call is not successful retention.
Report blocked lifecycle work explicitly rather than claiming completion.
